SM 从 188 降为 80 后 FA4 性能变化的定性和定量分析

核心原因：可用 SM 减少 57.45%，前向的计算和指令执行并行资源随之减少；decode 中访存主导或 grid 较小的场景，对 SM 数更不敏感。官方自动选型还会改变 tile、split 调度和 grid，给部分场景带来额外收益或退化。全量 285 项中，没有观察到减少 SM 新增的 register spill。

相对吞吐定义为 T188/T80；0.478× 表示同一输入的调用吞吐为基线的 47.8%，对应耗时 2.091×。本分析中的全量汇总来自原 285 项 CUDA Graph 计时，以下新补采只用于解释资源压力。

资源缩减模型与全量实测

80/188=0.425532，即只保留 42.55% 的 SM。假设频率相同、kernel 有足够任务、性能完全按 SM 数线性缩放，则相对吞吐约 0.4255×，耗时为 2.35×。每 SM RF 仍为 256 KiB，整卡 RF 总量从 47 MiB 降至 20 MiB；每 SM 的计算资源和寄存器比例没有改变。

Forward 的计算并行度下降

d128 MHA S8192 global 的主 kernel 为 2048 个 CTA，每 CTA RF 256 KiB，每 SM 最多 1 CTA。理论同时驻留容量从 188 CTA 降为 80 CTA；相同工作需要更多批次，按等成本 CTA 简化模型，约从 ceil(2048/188)=11 批增到 ceil(2048/80)=26 批。实际 CUDA Graph 耗时从 2.9699 ms 增为 6.3744 ms，约 2.146×。NCU 的每 SM achieved warp occupancy 两边都约 16.66%，但总共可执行的 SM 更少；不能用每 SM occupancy 不变推导整卡吞吐不变。

新补采在 GPU2、单 kernel、warmup 后执行，关闭 NCU 时钟锁定和 cache flush。d128 global 的 Tensor Active 为 86.89%→86.75%，DRAM 吞吐为 4.82%→2.19%。这支持该 kernel 主要受 SM 内 Tensor 执行资源影响，而非 DRAM 带宽饱和。

同一次 NCU 补采测得频率 2219.6→2336.9 MHz。仅按 SM 数和实测频率估算的耗时倍率为 (188×f188)/(80×f80)=2.2321；NCU 单 kernel 实测 2.9612→6.6240 ms，倍率 2.2369，差异约 0.22%。这解释了为什么实际减速可以小于同频线性模型的 2.35×。

上述频率模型严格对应同一次 GPU2 NCU 补采，不把 GPU2 的频率代入 GPU1 原始 CUDA Graph 数据来做精确分解。频率未锁定，不同采样时刻的数值可能变化。

Decode 的访存限制与小 grid

d64、B32、paged256、KV32768：原始 CUDA Graph 耗时 1.4017→1.4023 ms，几乎不变。新补采 DRAM 吞吐约 96.02%→95.95%，Tensor Active 5.23%→12.28%。80 SM 在该场景仍能接近占满整卡 DRAM 吞吐；增加 SM 未明显提高完成同一 KV 读取工作的速度。这是本次数据支持的访存带宽瓶颈实例，不能推广为全部 decode 均受 DRAM 限制。

d64、B1、dense、KV512：主 kernel 只有 64 个 CTA，少于 80 SM。减少到 80 SM 仍足以给每个 CTA 分配一个 SM，不必增加主 kernel 的最少执行批次；完整调用耗时在两边均约 5.345 μs。辅助 kernel 和固定执行开销同样不会简单随 SM 数线性缩放。

自动选型的独立影响

d256、B32、paged256、one_long_short128：188 SM 0.2660 ms；80 SM 固定调度 0.2657 ms，几乎不变；80 SM 自动调度 0.5214 ms，比固定组慢约 96.3%。自动组 grid 从 128 降至 64、combine 消失，RF/CTA 65→70 KiB，但并驻上限仍为共享内存限制的 1 CTA/SM，spill 仍为 0。主 kernel 的分区 DRAM 吞吐由固定组约 15.25% 降至自动组约 7.78%，伴随执行时间接近翻倍。证据支持并行任务划分与尾部负载问题，不支持把它归因于新增寄存器溢出；尚未通过只改变一个 split 参数的干预实验分离全部调度因素。

d96 MHA S8192 local1024 则相反：80 SM 自动选择使并驻上限 1→2 CTA/SM，RF/CTA 120→124 KiB，threads/CTA 160→128，共享内存 carveout 64→100 KiB，grid 4096→2048。CUDA Graph 耗时从 80 SM 固定组 0.8455 ms 降至 0.6596 ms，降低约 22.0%；新补采 Tensor Active 从 61.30% 升至 82.95%。它说明每 CTA RF 更大也可能更快，需要同时考虑 warp 分区、共享内存、tile 和任务数。

RF 容量的结论

全部 285 项固定调度组的每 CTA RF 分配、每 SM 并驻上限和 spill 计数均不变，自动组也没有新增 spill 或 spill 计数增加。205 项的理论并驻限制包含 registers，17 项原本就有 spill，原有 RF 约束仍然存在。减少 SM 会减少整卡同时可运行的 CTA 总数；它没有缩小单 SM RF，也没有使单 CTA 需要更多寄存器。

因此应区分三个因素：SM 执行资源减少、访存及固定开销不按 SM 数缩放、官方自动调度变化。本实验没有在计算资源不变时独立改变 RF 容量，不能给出“总减速中多少百分比由 RF 单独造成”的因果分摊。
