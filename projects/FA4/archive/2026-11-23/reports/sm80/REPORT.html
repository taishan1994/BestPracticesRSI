PR3109 全量前向场景的 188 SM 与 80 SM 寄存器对照

全部 285 个场景已完成三组计时、NCU 和数值对照：165 forward、120 decode，不含 backward。计时共 855 个场景组，NCU 共 1375 次 kernel launch，包含主 attention 和 prepare/combine。

容量结论：固定 188 SM 调度选择、仅将硬件资源限制为 80 SM 后，全部 kernel 资源存在变化的场景数为 0，spill 计数有差异的场景数为 0，从基线无 spill 变为有 spill 的场景数为 0。这些是本次范围内的观测，不等于 RF 对性能没有影响。

188 SM 基线中有 17 项已出现 NCU register-spilling 计数。80 SM 自动选择配置时，有 106 项主 kernel 配置或 grid 变化，有 0 项从基线无 spill 变为有 spill，有 0 项 spill 执行计数增加。自动选择产生的变化和固定配置对照必须分开解释。

以每个场景三组的 tokens/调用保持不变计算，相对吞吐 = 188 SM 耗时 ÷ 80 SM 耗时，188 SM 基线为 1.00×。固定配置组几何平均相对吞吐：forward 0.4782×，decode 0.8393×；自动组分别为 0.4797×、0.8411×。低于 1 表示比完整 188 SM 慢。

理论并驻限制中包含 registers 的主 attention 场景：188 SM 基线 205 项，80 SM 固定组 205 项，80 SM 自动组 205 项。该标记只说明寄存器限制可驻留 CTA 数，不单独证明其主导实际耗时。

实验范围

使用本机此前按 PR 公开范围重建的 285 项固定清单，并不是作者公布的原始 254 项逐行清单；作者原始 89 项 decode 的逐行身份尚未恢复。当前覆盖 BF16 d64/96/128/192/256、MHA/GQA/MQA、S512/2048/8192、global/causal/local1024，额外 FP16 d128 和 varlen；decode 覆盖 d64/128/256、B1/8/32/128、dense/paged256、多种 KV 长度分布。不穷举 softcap、score_mod/mask_mod、block sparsity、不同 Q/V head dimension 等所有可选功能组合。

硬件分区与对照设计

两张 GPU 均为 NVIDIA RTX PRO 6000 Blackwell Server Edition、SM120、188 SM，每 SM RF 为 65,536 个 32 位寄存器，即 256 KiB。GPU1 单独用于计时，GPU2 单独用于 NCU；同一张卡内部完成全部三组。计时和 profiler 并行运行在不同卡，未混用不同卡的耗时进行组间比较。PR 源码 commit 为 064643897f27c3d7b2058743d9e4dbdbf0d66325，74 个源码文件在启动前通过原始 SHA256 清单校验，没有修改 kernel。

  • full188_auto：实际 188 SM，官方自动选择配置。
  • green80_fixed188：CUDA Green Context 实际限制为 80 SM，官方 FLASH_ATTENTION_NUM_SMS=188 环境变量只固定 host planner 输入。它不是硬件限制手段。
  • green80_auto：实际 80 SM，不设置 SM 数覆盖变量，官方按当前 stream 的 80 SM 选择配置。

两张卡的驱动资源查询和硬件 %smid 探针均验证 188/80 SM；GPU1 另行捕获与重放探针 CUDA Graph，也实际观测到 188/80 个 SM；NCU 每个 launch 的 launch__sm_count 和 launch__uses_green_context 均逐项核对。没有修改主机驱动、MPS、时钟或功耗配置。

怎样读寄存器与 spill 数据

  • RF/CTA = NCU 硬件取整后的 allocated registers/thread × threads/CTA × 4 字节。它是实际分配容量，不是每条指令的 live register 数。
  • 最大 CTA/SM 来自 NCU 寄存器、共享内存、warp、block、barrier 等限制的最小值，包含 RF 分区约束，不能只用 256 KiB 除以 RF/CTA。
  • RF 满驻留百分比 = 每 CTA RF ÷ 256 KiB × 最大 CTA/SM，是容量上限，不是整卡时间平均 RF 使用率。小 grid 和尾波会降低实际驻留。
  • spill 计数使用 InstructionStats 的通用 sass__inst_executed_register_spilling，按该次 attention 调用中的全部 kernel 求和。计数反映执行的 spilling 指令活动，不是编译器 spill bytes/thread。
  • local load/store 使用 L1 local-memory sector 请求计数；它包含 local-memory 访问，不能无条件全部归为 spill，也不能当作实际 DRAM 字节流量。
  • NCU 的 local/shared 分类 spilling 子计数可能与通用计数不一致；保留原始值，但不用子计数替代通用计数判断是否有 spill。

计时方法与数值对照

每个 CUDA Graph 捕获 10 次 attention 调用，每个计时样本重放 10 次 graph，共 100 次调用；CUDA events 计时，9 轮内打乱三组顺序，报告每调用耗时中位数。采用 warm replay，没有显式刷新 L2，时钟未锁定；不与 PR 原文 cold-cache decode 数字直接比较。完整样本保存在 forward-timings.json 和 decode-timings.json。排序依据中位数，接近 1 的小幅差异不能直接视为稳定性能收益。

每场景三组共享相同输入张量；比较输出 finite 和 abs_diff ≤ 0.02 + 0.02×abs(reference)，参考为 188 SM PR 输出。这用于验证分区与调度切换没有引入超阈值偏离，不替代独立数学参考实现的精度验证。NCU 在另一进程、另一张同型号卡上，对 warmup 后的单次调用采集 LaunchStats、Occupancy、InstructionStats 和 local L1 计数，不把 profiler 内耗时当成性能结果。

结论适用边界

减少 SM 同时减少计算资源和整卡 RF 总量，并不缩小每个 SM 的 RF。Green Context 仍共享原卡的显存、带宽和缓存，不能等同于另一张物理上只有 80 SM 的 GPU。这套对照可以检测固定 kernel 的资源分配与 spill 是否变化，以及真实自动选择带来的差异；它没有在计算资源不变时独立改变 RF 容量，因此不能将全部减速归因于 RF，也不能证明 RF 的性能影响为零。任何关于优化收益的结论仍需进一步改变相关 kernel 配置并测量。
